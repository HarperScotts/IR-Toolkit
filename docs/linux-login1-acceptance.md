# Linux login1 只读实机验收流程

状态（2026-10-18）：已提供诊断命令与私有报告采集脚本；**真实 logind 主机验收仍未完成**。
容器中的私有 D-Bus + 合成服务只验证传输、状态和文件边界，不代表发行版/权限/真实会话覆盖。
本流程不安装依赖、不自动提权、不启动/重启/停止服务、不主动登录，也不修改审计/认证策略。

## 授权与范围

仅在已获授权的 Linux 主机、本地已有工具及普通用户权限下执行。目标需具备已有 `/usr/bin/busctl`
以及 `/run/dbus/system_bus_socket` 才可能成功；缺失、不兼容或拒读要保留为缺口，不应为通过
测试改系统配置。非 Linux 会明确拒绝，不能在 macOS 上运行诊断后声称 Linux 实机验收完成。

诊断只调用固定生产 login1 路径，另执行固定 busctl `--version`。不接收地址/可执行路径覆盖，
不使用 DBUS/PATH/LD_PRELOAD 等环境替换目标；无远程总线、无外网，无 shell 包装 busctl。
原始采集仍禁用服务自动启动和交互授权。普通权限失败并不授权改用 root；如需不同权限的验证，
先另行确认范围，将它作为独立实验记录，不能将其结果替换普通权限的失败。

范围不包含认证日志、utmp/wtmp/btmp、全进程扫描或完整 case 采集。它会读取 collector kernel
boot ID，执行已限额/超时的 login1 查询；读取和总线连接可能被系统正常记录，不承诺零环境扰动。
busctl 版本命令 context 2 秒；会话命令阶段总预算 10 秒、每命令 2 秒，另有进程清理延迟与前后
同步 proc boot ID 读取，不声称整个 I/O 都能严格中断。原始响应、身份、时间及用户信息均可能敏感。

## 执行与交付

在授权 Linux 开发环境，从仓库根目录，用独立临时构建目录（也可使用已验证的目标机二进制）：

```sh
task_login1_build=$(mktemp -d /tmp/ir-login1-build.XXXXXX)
GOPROXY=off go build -o "$task_login1_build/ir" ./cmd/ir
sh scripts/linux-login1-acceptance.sh "$task_login1_build/ir" "$task_login1_build/report"
```

构建要求已有 Go/模块缓存；`GOPROXY=off` 不自动下载模块，缺少时使用另行准备的受验证二进制。
脚本的两个参数必须为绝对路径；二进制必须存在且可执行。脚本固定基础工具 PATH/locale，先确认 Linux 和可用 SHA-256
工具，再用非 `-p` 的 mkdir 新建权限 0700 的叶目录。目录已存在（包括符号链接）则拒绝，
不覆盖旧报告/case；不删除失败目录。父目录路径由操作者选择，路径的真实性/父目录安全性
不是本脚本的认证保证，应选择受控的私有父目录，不使用共享可写目录中可被替换的路径。

新目录内文件默认 0600：

- `diagnostic.json`：`ir-login1-diagnostic-v1`，环境/有效 UID、busctl 版本原始字节与 hash、
  生产原始观察、实际 Analyzer 结果、分阶段检查和人工检查清单。
- `diagnostic.stderr`：原程序 stderr，包括失败诊断（当前 CLI 也可能输出错误栈）。
- `exit-code.txt`：诊断程序的实际退出码；非零不能改记为通过。
- `binary-before.sha256` / `binary-after.sha256`：运行前后二进制摘要，必须人工核对相同。
- `SHA256SUMS`：以上五份文件的摘要清单。摘要用于一致性，不认证二进制或主机真实性。

文件写入不是整体原子发布；突然终止可能只留下部分文件。缺文件、无效/不完整 JSON、摘要
不匹配、二进制前后摘要变化都视为未完成捕获，保留材料并另用新目录重试，不覆盖或修补旧结果。
脚本不验证任意输入二进制一定属于 IR-Toolkit；需核对构建/来源。只向授权接收方交付整个私有
目录，不公开诊断 JSON、stderr 或用户/主机标识。

只需要 stdout JSON 时可直接执行 `ir diagnose-login1`。命令先输出有结构的报告，诊断不完整时
返回非零；不创建 case 或写磁盘报告。不要把命令或脚本退出 0 当成实机验收通过。

## 报告解释

`automated_status=observed_subset` 仅说明该次工具版本读取、来源读取及支持的规范化步骤无错误；
即使列表为空也可能出现这一状态。`real_host_acceptance` **始终是 `not_attested`**，诊断程序
不能知道该主机是否为真实目标、操作者预期会话是否齐全或是否满足发行版支持矩阵。

| 检查 | 已观察到的结果 | 仍不能推出 |
| --- | --- | --- |
| busctl_version | 成功保留版本字节/hash，或明确错误 | 仅凭版本文本判断所有选项/接口兼容 |
| GetId/GetNameOwner/ListSessions | 调用/签名被实际路径接受，或保留错误 | 所有用户都可见、所有会话都覆盖或快照原子性 |
| GetAll | 有对象时逐对象读取；空列表为 not_exercised | 空列表意味着属性接口通过，或拒读/缺失等于 false |
| normalization | observed_subset / partial / skipped 与各记录诊断 | 认证成功、命令执行或已确认进程身份 |

`incomplete` 保留失败/部分来源；`unsupported` 表示非 Linux。分阶段状态来自实际调用状态，
不通过匹配本地化 stderr 文案猜测根因。按下面的顺序检查原始结果，不自动“修复”环境：

1. 工具版本调用失败：核对文件存在性/执行权限、选项支持；不要自动安装替代工具。
2. GetId 失败：核对固定本地总线的可见性/权限/容器命名空间；不要回退到 session/remote bus。
3. GetNameOwner 失败：记录 login1 是否本来就未运行/不可见；不要启动它来制造通过结果。
4. ListSessions 失败/解析被拒：保留 stdout/stderr 和版本，记录签名/格式/权限缺口。
5. 属性失败或对象消失：保留列表观察和逐调用错误；未知值不补为 false/0，变化不强行配对。

报告里的 `content`/`stderr` 原始字节通过 JSON Base64 保存；完整 uint64 创建微秒值为十进制
字符串。不要让表格或 JSON 客户端将其转成浮点数。创建时间、采集时间、活动时间不是同一概念。

## 人工验收清单（单独记录，不由工具代签）

记录主机授权标识、发行版/版本、架构、内核/boot 上下文、普通用户/有效 UID、busctl 版本、
IR 二进制来源与摘要、执行时间及报告目录。报告未自动读取发行版配置，不能凭 OS=linux 填成
已验收某发行版。将环境缺失、不适用、拒读与未执行分别登记，不使用统一的“通过”替代。

对照操作者本来已知、已授权观察的会话核对列表/UID/状态字段；不额外发起认证或创建会话。
若没有既有会话，标记属性读取与可见性范围“未覆盖”，不能人为填补覆盖度。
若自然发生会话变化，可独立捕获第二份新目录并比对原始来源 ID/路径/上下文；分析证据 ID
属于各次快照，不是跨快照稳定身份，不自动连接为同一会话或进程。

若还需验证完整 case/API/页面，另在授权范围内按标准 collect/analyze/Web 流程建立新 case，
核对 false/未知显示、来源告警、分页/详情与无越界跳转，并记录浏览器视觉结果。
本诊断包不是普通 case，不能直接交给 `ir web` 当作已采集 case。诊断成功不代替这些步骤。

完成记录需明确：已验证哪些发行版/工具版本/权限/自然变化场景，哪些没有执行；
附材料位置及人工结论。当前仓库验收记录中这些真实 logind 项目仍待执行。
